# 商品动态信息入库与知识库静态化 — 设计文档

日期：2026-08-27
分支：feat/kb-product-dynamic（从 feat/intent-recognition 开出）

## 背景与目标

现有商品知识库只有单份 docx（`llm_backend/knowledge_data/product_knowledge_docx/京东智能家具产品知识文档.docx`，由 `scripts/data/jd_smart_furniture.tsv` 经 `scripts/build_smart_furniture_docx.py` 生成），覆盖 50 款京东在售智能家具商品。问题：

1. 商品价格、库存属于**动态信息**，写死在 docx 静态知识中会快速过期
2. 售后政策稀疏：8 款商品售后列仅标"京东自营"无条款，多数为 "—"

**目标**：动态信息（价格/库存）入库存储，静态信息（参数/外观/政策）保留 docx 进向量库；京东自营售后政策独立成文档管理，商品文档引用之；提供测试用的少量/零库存数据。

## 分层原则

| 信息类型 | 存储位置 | 说明 |
|---|---|---|
| 动态信息（价格、库存） | `product_price_stock` 表 | 可更新，客服查询实时值 |
| 静态信息（参数、外观、售后政策） | docx → pgvector | 向量检索 |

## 1. 数据库新表 `product_price_stock`

新增模型 `llm_backend/app/models/product_price_stock.py`：

| 列 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | Integer | PK, index | |
| `product_name` | String(255) | NOT NULL, **UNIQUE** | 与 TSV 商品名称完全一致（查询/join 键） |
| `category` | String(50) | NOT NULL | 品类 |
| `current_price` | Numeric(10,2) | NOT NULL | 当前价格（元），TSV 参考价解析 |
| `stock_quantity` | Integer | NOT NULL | 库存数量，0 = 无货 |
| `updated_at` | DateTime | server_default=now(), onupdate=now() | 更新时间 |

- `init_db.py` 的 `Base.metadata.create_all` 幂等建表，无需额外 DDL（新增表，无存量兼容问题）
- 唯一约束：`UniqueConstraint("product_name", name="uq_product_price_stock_name")`

## 2. 数据导入脚本 `scripts/import_product_price_stock.py`

新建 `llm_backend/scripts/import_product_price_stock.py`（放 llm_backend/scripts，跟随 init_db 的 PYTHONPATH 模式）：

1. 读取 `scripts/data/jd_smart_furniture.tsv`
2. **价格解析规则**：从"参考价格(元)"列提取所有数字（含范围如"约4712-5154"、"5274(券后)"），多值取均值，四舍五入到分；**解析失败的行整行跳过不入库**（列 NOT NULL 无降级值），打印警告与行号，不中断整体入库
3. **库存填充规则**（测试数据，按 TSV 行序固定选取保证可复现）：
   - **0 库存（2 款）**：不同品类的 2 款商品（如取"智能晾衣机""智能门锁"品类行序第一），用于测试缺货应答
   - **少量库存（3 款）**：库存 = 2 / 3 / 5，取另外 3 个不同品类（如"电动智能沙发""智能床垫""电动升降桌"品类行序第一），用于测试紧张库存应答
   - **其余商品**库存 = 50（充足）
   - 选取规则写入脚本常量（按品类名 + 行序），与 docx 自营商品是否重叠无要求
4. upsert：按 `product_name` 幂等（存在则更新价格/库存，不存在则插入），可重复执行
5. 打印统计：入库行数、失败行数、零库存/少量商品清单

## 3. docx 变更（两个文件，格式与现有 docx 完全一致）

格式约定（现有 docx 样式分布：Heading 1×1 → Heading 2×9 品类 → Heading 3×50 商品 → Heading 4×250 子章节 + List Bullet/Normal 正文，无自定义字体，全部默认样式）：

### 3.1 商品知识文档（`scripts/build_smart_furniture_docx.py` 重生成）

1. **移除** `add_product` 中"参考价格"段落（价格归数据库），商品信息章节保留品牌/品类
2. **自营商品引用**：TSV 售后列 = "京东自营" 的 8 款商品，其 H4 售后服务章节写一条要点："本商品为京东自营，适用《京东自营售后政策》（独立知识文档，已随知识库上传）"；其余商品保留现有真实售后文本（未变）
3. 文档说明段落补充一句：商品价格与库存为动态信息，存储于系统数据库中，本文档不包含（保持 Normal 样式）

### 3.2 独立售后政策文档《京东自营售后政策》（新建 `scripts/build_jd_aftersales_docx.py` 生成）

- 新文件 `llm_backend/knowledge_data/product_knowledge_docx/京东自营售后政策.docx`（与商品文档同目录，一并上传索引）
- 内容为网络检索京东官方帮助中心（help.jd.com）整理的平台售后政策：
  - H1 标题《京东自营售后政策》
  - H2 章节：七天无理由退货、价格保护、售后流程、运费与上门取件、商品类目差异说明等
  - 关键条款用 List Bullet 呈现，H2 章节尾部 Normal 段落附对应来源链接
- 内容独立于 TSV（来源为京东官方页面检索结果），单独脚本生成以便单独维护更新
